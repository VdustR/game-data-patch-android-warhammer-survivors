## Repository hardening

Eight additional tests exercise the real release and source-gate scripts against an isolated Git/GitHub fixture. They cover unexpected/private artifacts, links and missing payloads, interrupted draft upload and retry, published-release immutability, corrupt downloads, dirty sources, tag conflicts, API failures, exact-main CI acceptance, and stale automatic/manual runs. These fixtures model recorded GitHub response fields; they do not establish host-side behavior by themselves. Release acceptance also requires the actual workflow and downloaded artifact checksums.

The CLI reads at most the configured 5 MiB limit plus one byte from the validated file handle. The browser disables version consent along with the other inputs during generation and recovers after a failed digest. No new dependencies or device permissions were added.

The installation skill now stops the game before copying the current main and backup files. Two instruction scenarios were checked twice: a running game must stop before either copy, and a failed patch restores the preserved pair while the game is stopped. These are procedure checks; the audit did not repeat hardware or cloud-persistence testing.
